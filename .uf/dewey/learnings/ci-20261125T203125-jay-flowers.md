A major-version bump of stefanzweifel/git-auto-commit-action (v5 to v7) in mega-linter.yml needs an input-compatibility check that a red/green PR check does not provide: the workflow passes branch, commit_message, commit_user_name, and commit_user_email positionally, and MegaLinter applies fixes and exits 0 before the commit step runs, so a renamed or removed v7 input degrades silently to the action default — the workspace is fixed but uncommitted and the MegaLinter job stays green. The drift appears only on the next full-codebase run on main and then blocks release preflight (which requires MegaLinter success). Verify the action.yml input list at the pinned SHA (gh api repos/stefanzweifel/git-auto-commit-action/contents/action.yml?ref=<sha>) and that push semantics stay non-force. Related bounds that make this LOW rather than HIGH: the commit step is gated on github.ref != 'refs/heads/main' so it never runs on main and cannot affect release artifacts; dependabot.yml groups github-actions at minor/patch only so majors arrive individually; and dependabot-automerge.yml leaves third-party updates for a person.
