When a change adds a second same-package construction site for an established workspace path, extract the single-definition helper in the same PR. The dewey tools package already models this: Compile owns compiledDir() (tools/compile.go:96) for .uf/dewey/compiled, but Learning rebuilt filepath.Join(vaultPath, deweyWorkspaceDir, "learnings") inline in writeLearningFile, and PR #156's new learning_temporal.go added a second inline copy in markSupersededFile before review feedback (divisor-architect, LOW/dry) caught it. Duplicated workspace-path definitions diverge silently under relocation: .uf/dewey/learnings is a contract between the file writers and the startup re-ingestion sweep (main.go reIngestLearnings), so a site missed during a move strands backups outside recovery. Scope the helper to same-shape, same-package sites (absolute paths, methods on the same handler struct); vault-relative reporting forms and cross-package consumers stay separate rather than being forced through one definition.
